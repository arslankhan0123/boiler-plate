Getting started with Orchid

Everything you need to install, customize, and extend the Orchid Bootstrap 5.3 admin template.

TL;DR

Orchid is pure HTML + external CSS + vanilla ES6 JavaScript with zero build step. Open index.html in any modern browser and you're done. All customization happens in editable text files.

Quick start

Three ways to get running:

Open directly

Double-click index.html. Zero setup.

Local server

Run npx serve for cleaner asset paths.

Deploy

Upload the folder to any static host.

Preferred workflow with a local server (any of these):

# Node.js
npx serve .

# Python 3
python -m http.server 8000

# PHP
php -S localhost:8000

Then open http://localhost:8000 in your browser.

Brand & logo

The Orchid brand appears at the top of the sidebar in every admin page. Find it inside .orchid-sidebar__brand:

<a href="#" class="orchid-brand">
  <span class="orchid-brand__logo">
    <svg viewBox="0 0 32 32">...</svg>   <!-- Replace with your logo -->
  </span>
  <span class="orchid-brand__text">Orchid</span>   <!-- Replace with your name -->
</a>

The brand-name gradient lives in assets/css/orchid.css under .orchid-brand__text. Replace the favicon at assets/icons/favicon.svg.

Colors & themes

All brand colors are CSS custom properties in assets/css/orchid.css. Change them once, updates propagate everywhere.

:root,
[data-bs-theme="light"] {
  --orchid-bg:         #f5f6fa;
  --orchid-surface:    #ffffff;
  --orchid-border:     #e9ecf3;
  --orchid-text:       #1e2436;
  --orchid-text-muted: #6b7385;
  --orchid-primary:    #4f46e5;   /* ← your brand color */
  --orchid-accent:     #22d3ee;
}

[data-bs-theme="dark"] {
  --orchid-bg:         #0f1220;
  --orchid-surface:    #171a2b;
  --orchid-border:     #232842;
  --orchid-text:       #e6e8f2;
  --orchid-primary:    #818cf8;   /* lighter in dark */
}

If you prefer SCSS, the same tokens live in assets/scss/abstracts/_variables.scss — recompile after editing (see Compiling SCSS).

Typography

Orchid uses Inter by default. To change:

1. Swap the Google Fonts import in every HTML <head>:

<link href="https://fonts.googleapis.com/css2?family=Inter:wght@300;400;500;600;700;800&display=swap" rel="stylesheet">

2. Update the CSS body font-family in assets/css/orchid.css:

body.orchid-body {
  font-family: 'Inter', -apple-system, BlinkMacSystemFont, sans-serif;
}

Dark mode

Dark mode is powered by the data-bs-theme attribute on <html> and managed by assets/js/theme.js.

How it works
  • Click the sun/moon toggle button (data-orchid-theme-toggle) in any header.
  • Preference is saved to localStorage['orchid-theme'].
  • On page load, JS reads the stored preference (falling back to OS prefers-color-scheme).
  • A orchid:themechange event fires so charts can rebuild with fresh colors.

To force one theme site-wide, set <html data-bs-theme="dark"> at the top of each page and remove the toggle button.

Sidebar menu

The sidebar is identical HTML across all 141 admin pages so users can navigate freely. Edit menu items by modifying the <aside class="orchid-sidebar"> block. Two link types:

Flat top-level link

<li>
  <a href="my-page.html" class="orchid-nav__link">
    <i class="bi bi-star"></i><span>My Page</span>
  </a>
</li>

Collapsible section with sub-links

<li>
  <a href="#navMyGroup" class="orchid-nav__link orchid-nav__link--has-sub collapsed"
     data-bs-toggle="collapse" role="button"
     aria-expanded="false" aria-controls="navMyGroup">
    <i class="bi bi-folder"></i><span>My Group</span>
    <i class="bi bi-chevron-down orchid-nav__chevron"></i>
  </a>
  <ul class="collapse orchid-nav__sub list-unstyled" id="navMyGroup">
    <li><a href="child-a.html" class="orchid-nav__sublink">Child A</a></li>
    <li><a href="child-b.html" class="orchid-nav__sublink">Child B</a></li>
  </ul>
</li>

On each page, mark the active link with class="… active" aria-current="page". For sublinks, also add show to the parent <ul> and switch collapsed→trail-active on the toggle.

Add a new page

The fastest way to add a new page is to duplicate index.html and edit five things:

  1. Filename — save as my-page.html at the repo root.
  2. Title — <title>Orchid — My Page</title>
  3. Breadcrumb — change the .breadcrumb items inside the header.
  4. Active sidebar link — mark the matching .orchid-nav__link or .orchid-nav__sublink as .active.
  5. Main content — replace everything inside <main class="orchid-main">. Keep the footer.

Optionally add a page-specific CSS and/or JS file:

<!-- Add after orchid.css -->
<link href="assets/css/pages/my-page.css" rel="stylesheet">

<!-- Add before </body> -->
<script src="assets/js/pages/my-page.js" defer></script>

Page shell anatomy

Every admin page has the same skeleton:

<body class="orchid-body">
  <a class="visually-hidden-focusable" href="#orchid-main">Skip to main</a>
  <!-- 1. Sidebar (identical on every page) -->
  <aside class="orchid-sidebar" id="orchidSidebar">...</aside>
  <div class="orchid-backdrop"></div>
  <!-- 2. App wrapper -->
  <div class="orchid-app">
    <!-- 3. Header (identical on every page) -->
    <header class="orchid-header">...</header>
    <!-- 4. Main content (unique per page) -->
    <main class="orchid-main" id="orchid-main" tabindex="-1">
      <div class="container-fluid px-3 px-lg-4 py-4">
        <!-- Your page content here -->
      </div>
      <!-- 5. Footer (identical on every page) -->
      <footer class="orchid-footer">...</footer>
    </main>
  </div>
  <!-- 6. Scripts -->
  <script src="…bootstrap.bundle.min.js"></script>
  <script src="…chart.umd.min.js"></script>
  <script src="assets/js/theme.js" defer></script>
  <script src="assets/js/sidebar.js" defer></script>
  <script src="assets/js/charts.js" defer></script>
  <script src="assets/js/orchid.js" defer></script>
</body>

Charts (Chart.js)

Charts render into <canvas> elements inside a bounded-height container. Always wrap with a div that has an explicit height.

<!-- HTML -->
<div class="orchid-chart-wrap orchid-chart-wrap--lg">
  <canvas data-orchid-chart="myChart"></canvas>
</div>

// JS — assets/js/pages/my-page.js
new Chart(document.querySelector('[data-orchid-chart="myChart"]'), {
  type: 'line',
  data: { labels: [...], datasets: [{ data: [...] }] },
  options: {
    responsive: true,
    maintainAspectRatio: false   // important!
  }
});
Common gotcha

If a chart keeps growing taller and taller, its parent has no explicit height. Either use one of the .orchid-chart-wrap--sm/md/lg classes (120/180/280px) or set height: 200px on the wrapper.

Charts should rebuild on theme change. Store instances in a Map, then:

document.addEventListener('orchid:themechange', () => {
  instances.forEach(c => c.destroy());
  initCharts();  // rebuild with new palette
});

Data tables

Use .table.orchid-table for lightweight styled tables, or clone the users.html markup for full CRUD (search, sort, filter, bulk actions, pagination). The complete controller lives in assets/js/pages/users.js. To reuse:

  1. Copy the table markup + toolbar + bulk-action bar from users.html.
  2. Rename data attributes if you want a separate namespace.
  3. Feed the JS controller your own dataset by editing the USERS constant.

For a simpler tabbed data grid, see tables-data.html which uses data-tables-data-grid attributes and assets/js/pages/tables-data.js.

Forms & validation

Orchid uses Bootstrap's .was-validated pattern:

<form novalidate class="needs-validation">
  <input class="form-control" required>
  <div class="invalid-feedback">Please enter a value.</div>
</form>

// JS
form.addEventListener('submit', e => {
  if (!form.checkValidity()) { e.preventDefault(); e.stopPropagation(); }
  form.classList.add('was-validated');
});

For richer forms — wizards, file uploads, custom date/time/color pickers, rich text editors — see forms-*.html and assets/js/pages/forms-showcase.js which exposes window.OrchidForms.{initWizard, initDatePicker, initTimePicker, initColorPicker, initRichEditor}.

Modals & offcanvas

Use Bootstrap 5.3's data attributes — no JS required to open/close:

<!-- Trigger -->
<button data-bs-toggle="modal" data-bs-target="#myModal">Open</button>

<!-- Modal -->
<div class="modal fade" id="myModal">
  <div class="modal-dialog modal-dialog-centered">
    <div class="modal-content">...</div>
  </div>
</div>

Tip: for a scrollable body with a sticky footer, add modal-dialog-scrollable. If you wrap .modal-body + .modal-footer in a <form>, add form { display: contents } so the flex layout still works.

Toasts

Most page-specific JS modules expose a orchidToast(message, variant) helper. Variants: success, info, warning, danger.

orchidToast('Changes saved', 'success');
orchidToast('Something went wrong', 'danger');

Images & avatars

Orchid uses external CDN images with automatic 404 fallback:

  • Portrait avatars (contacts, employees, support agents) — https://i.pravatar.cc/160?u=<seed>
  • Product photos — https://images.unsplash.com/photo-<id>?auto=format&fit=crop&w=480&h=360&q=70
  • 404 fallback — any image that fails swaps to https://picsum.photos/seed/<seed>/w/h

To use your own images, replace the CDN URLs with local paths and put your assets in assets/images/.

Compiling SCSS

Compiled CSS is shipped, so SCSS compilation is optional. If you want to edit SCSS sources:

npm install -g sass

# One-off build
sass assets/scss/orchid.scss assets/css/orchid.css --style=compressed

# Watch mode
sass --watch assets/scss/orchid.scss:assets/css/orchid.css

Strict rules (CSP-compliant)

Every admin page passes strict Content-Security-Policy audits. When customizing, keep these rules:

Never use
  • style="..." inline attributes
  • <style> blocks inside HTML
  • Inline event handlers (onclick, onchange, onsubmit, etc.)
  • href="javascript:..." URIs
Instead
  • Put styles in an external .css file (add utility classes if needed).
  • Attach events in an external .js file via addEventListener.
  • Use data-* attributes as hooks — read them from JS.
  • Setting element.style.width in JS is fine — it's a runtime DOM API, not an inline HTML attribute.

Two exceptions ship with Orchid intentionally: landing.html and documentation.html (this file) use inline styles because they're standalone marketing pages, not admin app pages.

Browser support

Latest two major versions of:

Chrome Edge Firefox Safari

Internet Explorer is not supported. IE11 doesn't support CSS custom properties, clip-path: inset(), or display: grid at the level Orchid uses them.
